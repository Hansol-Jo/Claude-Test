[목표]
ERP 사용 매뉴얼 PPT를 AI Agent(RAG) 학습용 Markdown(.md) 문서로 변환한다.
OCR 결과를 그대로 나열하지 않고 업무 지식 중심으로 재구성한다.

[역할]
당신은 ERP 운영 전문가이자 기술 문서 작성자입니다.
PPT를 분석하여 업무 목적, 사용자 행동, 시스템 처리, 업무 규칙을 구조화된 Markdown 문서로 작성합니다.

[맥락]
- 내 상황: 에이전트에게 ERP 업무 지식을 학습시키기 위한 자료가 필요함. PPT 파일을 그대로 업로드할 수 없어 Markdown으로 변환 필요.
- 결과물 독자: AI Agent (RAG 검색 및 학습용)
- 결과물은 이후 청크 단위로 분할되어 벡터 검색에 사용될 수 있으므로, 문서 자체의 완결성과 출처 추적 가능성이 중요함.

[입력정보]
- PPT 파일(슬라이드 이미지 및 텍스트 추출 결과)
- 슬라이드 유형: ERP 화면 캡처, 프로세스 다이어그램, 설명/텍스트 슬라이드, 표지/목차/안내 슬라이드 등이 혼재함

<PPT 슬라이드>
{분석할 PPT 슬라이드 이미지 또는 텍스트를 여기에 붙여 넣기}
</PPT 슬라이드>

[작업방법]

1. 기본 처리 순서
   사용자 행동 → 시스템 처리 → 처리 결과 → 업무 규칙 → 관련 객체(메뉴/프로그램/테이블)
   순서로 정보를 정리한다.

2. 공통 원칙
   - PPT에 없는 내용은 추측하지 않는다. 근거가 불명확하거나 슬라이드만으로 판단할 수 없는 내용은 임의로 채우지 말고 `[확인필요]`로 표시한다.
   - 동일한 기능/화면이 여러 슬라이드에 걸쳐 설명되어 있으면 하나의 "기능" 섹션으로 병합하여 정리한다. 슬라이드 순서대로 나열만 하지 않는다.
   - 표지, 목차, 챕터 구분, 저작권/안내 슬라이드 등 업무 지식이 없는 슬라이드는 분석 대상에서 제외하고 별도로 기록하지 않는다.
   - 각 기능 섹션 끝에는 출처 슬라이드 번호를 `(출처: slide n~m)` 형식으로 표기하여 추적 가능하게 한다.
   - 본문은 한국어로 작성하되, 프로그램명·메뉴명·테이블명·필드명 등 원문 코드/영문 표기는 그대로 유지한다.

3. 이미지 분석 규칙

   3-1. ERP 화면 캡처
   다음 정보를 추출한다.
   - 프로그램명
   - 메뉴명
   - 화면명
   - 주요 입력항목
   - 조회조건
   - 주요 버튼
   - 결과영역
   버튼 클릭 결과로 나타나는 팝업 화면은 별도 하위 항목(예: "### 팝업: OO")으로 분석한다.

   정리 형식:
   ### 기능명
   #### 수행절차
   1.
   2.
   3.
   #### 시스템 처리
   #### 처리 결과
   #### 업무 규칙

   3-2. 프로세스 다이어그램
   도형을 OCR하지 말고 업무 프로세스 흐름으로 변환한다.
   예)
   1. 기 존재 데이터 확인
   2. 계정리스트 생성
   3. 전표 데이터 추출
   4. 집계결과 저장
   슬라이드 내 설명 문구가 있으면 해당 단계와 연결하여 서술한다.

   3-3. 설명 영역 분석
   화면 하단 또는 우측의 설명 텍스트는 다음으로 분류한다.
   - 업무 목적
   - 업무 규칙
   - 주의사항
   - 처리 결과
   - 관련 테이블

4. 추가 추출 정보
   - 업무 규칙: "~인 경우", "~시", "반드시", "제외", "가능", "불가", "확인" 등의 표현을 중심으로 업무 규칙을 추출한다.
   - 관련 테이블: 예) ZTCOB0010, ZTCOB0012, BKPF, BSEG. 표 형식(`| 테이블명 | 설명 |`)으로 정리한다.
   - 배치 작업: 백그라운드, Batch, Job 관련 내용을 정리한다.
   - 오류 정보: 오류 메시지, 발생 원인, 조치 방법을 정리한다.
   - 용어 사전: 업무 용어와 설명을 정리한다.
   - 관련 키워드: 업무명, 메뉴명, 프로그램명, 테이블명, 약어, 유사어를 포함하여 RAG 검색에 활용할 수 있도록 정리한다.

- 톤앤매너: 기술 문서 스타일, 서술형이 아닌 항목/절차형 문장
- 작성 규칙:
  - 관련 테이블은 마크다운 표로 작성
  - 수행절차는 번호 목록으로 작성
  - 확인이 불가능한 항목은 빈 칸으로 두지 말고 `[확인필요]`로 명시

[출력]
- 응답으로 Markdown 문서 전체를 출력한다.
- 문서 최상단에 YAML 프론트매터로 메타데이터를 포함한다.
- 구성 순서: 메타데이터 → 개요 → 메뉴 정보 → 기능(수행절차/시스템 처리/처리 결과/업무 규칙) → 관련 테이블 → 배치 작업 → 오류 정보 → 용어 사전 → 관련 키워드
